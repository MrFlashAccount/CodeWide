# Claude provider adapter

## Purpose and owner

The Rust `AgentProvider` implementation for Claude. It owns the Claude configuration (`providers.claude` in `agent-providers.json`) and drives the user's own `claude` CLI directly over its stream-json protocol: one `claude` process per live thread, one session actor per thread, behind a thread service that keeps CodeWide's own per-thread metadata and reads and writes Claude's session store. There is no separate host process and no Claude Agent SDK; the protocol semantics the former TypeScript host implemented are ported here, and the neutral shapes stay in [`packages/agent-protocol`](../../packages/agent-protocol/CONTEXT.md). With host storage attached, the adapter also keeps an index of Claude's session store and serves the thread list, indexed history, discovery, message search and thread resources from it. It depends on `agent-core`, `agent-index`, `agent-search`, `agent-resources` and `companion-host`. Code owner: backend. This document: architect. Layer contract: [`crates/companion-core/src/agent/CONTEXT.md`](../companion-core/src/agent/CONTEXT.md).

## Module jobs

- `src/lib.rs` — `ClaudeProvider`: wires the thread service, the storage and index, the runtime probe and account, the companion's client tools and the published rate limits; routes each `AgentProvider` call to the index (while fresh) or the thread service; stamps provenance on every turn and item it returns or emits. Capabilities are the constant `CAPABILITIES` plus the storage-dependent flags (see [Capabilities](#capabilities)).
- Health: unavailable when Claude cannot start on this host (no configuration directory, unreadable proxy settings, a thread state directory that cannot be opened; logged once at `error`), otherwise available with the sign-in state the runtime probe read. Only the authenticated flag, the plan label and the account label (email or organization) pass; none is a credential, and no label is logged. Prices: the probe's model list carries the price table, which fills the adapter's `CatalogPricing` (`AgentProvider::usage_pricing`). Subscription limits: `runtime/published_limits.rs` publishes the latest merged snapshot (`AgentProvider::subscribe_rate_limits`; `None` until the first report). The descriptor's `version` is the `claude --version` output, read once at start.
- `src/cli/` — the `claude` process without the SDK: `command.rs` (the command line per permission profile, as the SDK built it for a streamed query: stream-json in and out, partial messages, adaptive thinking, `--permission-prompt-tool=stdio`, `--replay-user-messages` for Claude's `command_lifecycle` of each companion message, model, effort, tools, setting sources, MCP config), `protocol.rs` (the stream-json lines: user messages with priority, the companion's control requests `initialize`, `interrupt`, `set_permission_mode`, `get_usage`, Claude's control requests `can_use_tool` and `mcp_message`; inbound lines are classified structurally and never fail), `process.rs` (one process, started with `CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS=1` so Claude reports `session_state_changed`: requests `codewide-<n>` with their answers, Claude's requests and messages as ordered events, the last 8 KiB of stderr for the error a failed process reports), `mcp.rs` (the companion's client tools as the in-process MCP server `codewide`, answered over `mcp_message`; a failed tool is an `isError` result).
- `src/session/` — the live session of one thread: one actor (tokio task, `actor.rs`) owns the thread's `ThreadState`, its query and its active turn and handles commands, query events and timers one at a time; `turn.rs` (start, continue with Claude's resume prompt as an adapter message, steer, interrupt, results, a lost session's replacement, usage, background task reports as `taskNotification` items, and the turn's boundaries — see [Turn boundaries](#turn-boundaries)), `task_reports.rs` (which live reports reach the main conversation — not a task a sub-agent owns, not a foreground call still open — and the reports waiting while idle, delivered once by the next turn and dropped when the query ends; what the open query knows of one task for an output read; the background commands the open query launched, each with its latest `command` item and turn: a final report republishes that item with its end at once, delivered or waiting — a report of an earlier query's launch, as Claude sends for each task it finds orphaned on resume, republishes the stored launching item (`HistoryLines::launch`, the newest 400 turns) —, and the query's end republishes a still-running one as `unknown`), `requests.rs` (`can_use_tool` and client tool calls; user answers and their cancellation; a sub-agent's call — `agent_id` — is never an item of the conversation's turn and wakes a provider turn only for a question or approval the user answers or a client tool call), `settings.rs` (when settings take effect), `client_tools.rs`, `query.rs` (the query port: a `claude` process or a test double; a `claude` whose `initialize` answer has no `session_state` is unsupported), `ports.rs` (what the actor needs from its owner), `handle.rs` (`SessionHandle`). `replay_tests.rs` replays every recorded transcript (`fixtures/replay/*.ndjson`) through a real session with a scripted query and compares the neutral events with `fixtures/golden/*.neutral.jsonl` (time fields blanked; `thread.updated` is checked separately in `threads/tests/golden.rs`).
- `src/threads/` — `ThreadService`, the `codewide-agent` v1 operations over Claude's store: create, fork, read, owns, list, turns, update (name, archive, settings, delete), compact and the turn operations (`thread_ops.rs`, `turn_ops.rs`); the session actor registry and session chain index (`registry.rs`); projections onto `AgentThread` and list rows (`projection.rs`); Claude's listing with cached session metadata (`session_catalog.rs`); a thread's history from the offset index (`history.rs`: every read first catches the index up with the thread's sessions — only what was appended since their checkpoints — then reads the byte ranges of the turns it needs: `thread.turns` pages with the live turn's snapshot, the known-turn check, the fork cut (the boundary turn found by id and its last stored message read from its range alone), a replacement session's history prefix (newest pages until 16 KiB of lines), and the recorded model of a discovered session (kept with the session file's checkpoint)); `ThreadService::attach_index` receives the storage's `SessionIndex`, else one kept in memory, so no service read takes a session whole; startup (`startup.rs`: load every stored thread, convert v1 journals, finalize turns left in progress as interrupted, then publish every listed thread's authoritative lifecycle status after a confirmed running-session read); the ordered output stream (`outputs.rs`); open-elsewhere integration. A failed running-session read publishes no startup status snapshot, so absence of process evidence never settles a thread. Threads are CodeWide's own (companion-minted ids) and sessions Claude already has (session id = thread id).
- `src/background_tasks/` — background task output (`thread.backgroundTask.read`, `threads.backgroundTaskOutput`): `task_id.rs` (a task id is 1–64 ASCII letters and digits, so it can only name `<task id>.output`), `facts.rs` (pure: whether the thread's own items launched the task — a `command` item's `background` task — or were reported it — a `taskNotification`'s `taskId` —, the output path the launching result names, and the status: newest final report, else the live session's knowledge, else `unknown`), `output_file.rs` (where Claude writes the output, `<temp root>/claude-<uid>/<project key>/<session id>/tasks/<task id>.output` for the sessions of the thread's chain, with the uid and project key of each session file; the temp root the `claude` children inherit or the root of the claimed path when it ends with exactly those components; canonicalized directory, `O_NOFOLLOW`, regular file owned by the session owner; at most `limit` + 6 bytes read; paths never logged), `page.rs` (pure: which bytes of a read window are the page, on UTF-8 boundaries), `read.rs` (the answer: status and page, or `-32074`). Every `thread.turns` answer, from the index or the thread service, passes through `ThreadService::overlay_live_background_commands`, asked only when a page has a launch that has not ended: the open query's states (`SessionHandle::background_commands`) — and a launch the open query does not know belongs to an earlier process generation, so it stopped by the query's start (a new query opens only when no process holds the session, and Claude itself reports such tasks orphaned on resume) —, else the process that holds the session (`OpenElsewhere::activity`, retried with backoff while unreadable): one that started no later than a launch still runs it, a later generation or none proves it `stopped` (at that generation's start, else when the service first saw it gone, kept in `ServiceInner::background_losses`), an unreadable list keeps it `running` (`background_commands::held_state`). The query's process exiting stops its running tasks; a query the companion closed does not, since `claude` keeps running while its tasks do. `src/lib.rs` validates the id, rejects child threads, scans `thread.turns` newest first until the launching call and answers off the async runtime. `src/threads/background_task_ops.rs` gives the thread's session files (newest first) and what its live session knows of the task (`SessionHandle::background_task`, from `session/task_reports.rs`: tasks started in the open query and the status of every report it received; forgotten with the query).
- `src/state/` — the single owner of `<journal>/threads/<app thread id>/state.json` (`ThreadState` v2) and `active-turn.json`, read and written atomically (temporary file, fsync, rename; directories 0700, files 0600), and the one-way conversion of the former v1 journal. The JSON is the format the TypeScript host wrote, field for field, so existing threads keep their ids, turn ids and `clientMessageId` echoes.
- `src/live/` — pure rules of a live session: `usage.rs` (turn usage as differences of Claude's cumulative per-model totals against persisted checkpoints; the live meter; context windows), `permissions.rs` (approval and user-input requests, decisions, what each profile may ask; fail-closed), `prompt.rs` (user content as Messages API blocks; the bounded history prefix for a replacement session), `rate_limits.rs` (`rate_limit_event` frames and `get_usage` answers merged into `ProviderRateLimits`, including the validated raw `rate_limits.cedar_ember` banked-reset inventory; live usage reads at most every two minutes).
- `src/runtime/` — services around the CLI: `probe.rs` (a short-lived `claude` that answers only `initialize`: account, models and, best effort, the plan's usage; no model call), `account.rs` (sign-in state and model catalog; probed at start; a catalog read probes first while no model is known or the user is signed out, and otherwise answers the cached list at once and probes in the background when the last probe is a minute old), `models.rs`, `prices.rs` (Anthropic API list prices), `recorded_model.rs`, `cli_version.rs`, `running_sessions.rs` and `open_elsewhere.rs` (sessions another `claude` process holds, from `claude agents --json`; the cached authority includes `startedAt`, so disappearance or replacement of a process generation invalidates unfinished indexed work; no turn runs in a held session and its thread is `openElsewhere`), `proxy_environment.rs` (the standard proxy variables of the user's Claude `settings.json` `env`, forwarded to every `claude` process), `rate_limit_reset.rs` (one user-confirmed `cedar_ember` reset request using Claude's freshly probed OAuth credential, serialized and never logged), `companion_tools.rs` (the `ClientToolHost` the companion installs once), `published_limits.rs`.
- `src/config.rs` — validation of the `providers.claude` entry (`ClaudeConfig { claude_executable, journal_directory, idle_release_minutes, environment }`), the children's environment and the session store it implies. `src/discovery.rs` finds the user's `claude` and login-shell `PATH` (`ClaudeDefaults`).
- `src/preflight.rs` — offline check that `claudeExecutable` could start under that environment (an executable file; its `#!` interpreter on the children's `PATH`); used by `codewide-companion providers status`. `companion-core`'s `agent/providers/mod.rs` hands the entry to it and spawns the adapter (`spawn_with_storage` with the companion's `ProviderHost`); `registry.rs` treats the entry as opaque.
- `src/legacy_install.rs` — the former host's files, removed on start: the installer's directories (Linux `~/.local/lib/codewide/claude-agent-host` and `…/claude-sidecar`, macOS `~/Library/Application Support/CodeWide/ClaudeAgentHost`), `<state dir>/claude-agent-host` and `<state dir>/claude-agent-sdk`.
- `src/uuid.rs` — random v4 UUIDs for the ids Claude persists (sessions, messages, prompt offers).
- `src/store.rs` — `ClaudeStore`: the session index in the companion's index database (`state.redb`), migrated through `companion-host`'s `DerivedIndexSchema` (`CLAUDE_INDEX_SCHEMA`, logic version `claude_index_logic_version`, 17 since turns are byte ranges of Claude's files; a change drops and rebuilds the tables, other tables are untouched, and the former copies of whole turns, `claude_session_turns` and `claude_subagent_turns`, are dropped). Tables: `claude_sessions` (`StoredSession`: listing facts, the session file and its sub-agent transcripts, the process activity the last pass saw, the turn index hints the file was scanned with, and the aggregates of its turn digests: sub-agents, whether a person's turn exists, the newest message's preview), `claude_thread_sessions`, and the shared segmented offset index `CLAUDE_SEGMENT_TABLES` (`claude_index_*`: files, turns, turns by id, tombstones, record keys, scan states, turn start states, facts, and `claude_index_turn_digests`: one `TurnDigest` per turn — preview, person's turn, sub-agent launches, resources, never the turn). No row holds a turn. A thread's history is its sessions' turns, oldest session first, one turn per id (a turn interrupted by a lost session reappears in its replacement session; the later share wins). Deleted threads are neither served nor searchable. It publishes each thread's working directory and times to the companion thread index (`HostThreadIndex`), and one row per sub-agent child thread under its parent.
- `src/subagents.rs` — sub-agent child threads (their thread-index rows carry `running`, the only status a client gets for a Claude child, since it has no live thread of its own): the id format `<app thread id>:agent:<agent id>` (minted on `subagent` items), the facts indexed per sub-agent (description, agent type, times, running, the model its transcript last answered with and the effort recorded on that answer), the read-only `AgentThread` of a child and its thread-index row. A child's settings are the parent thread's access (`permissionProfile`, from the parent chain's CodeWide settings else the discovered ones, `catalog::thread_settings`), its transcript's model, else the parent's, and its transcript's effort (the top-level `effort` Claude Code writes on each answer: the effective value of an explicit `Agent` `effort`, else the agent definition's, else the session's for the agent's model); an unrecorded effort stays unknown and is never the parent's; service tier is not reported. A changed model alone does not make the sub-agents list differently: the thread-index row carries no model. `src/lib.rs` answers `thread.read`, `thread.turns` (fenced reads take their fence from the thread service's output stream) and `thread.owns` of child ids from the index.
- `src/watcher.rs` — change detection on Claude's session store (`$CLAUDE_CONFIG_DIR/projects` or `~/.claude/projects`, `<project>/<session id>.jsonl`): size and modification time only, a debounced rescan on filesystem events and a periodic rescan. It never opens a session record.
- `src/transcript/` — Claude's transcript format in Rust (pure): structural records and frames (`json.rs`, `frames.rs`), tool calls to neutral items (`tools.rs` — a background `Bash` call's `command` item carries its validated task as `background`, `running` at launch —, `shell_tools.rs` — `Bash` and `Monitor` calls are `command` items naming the background task they started (`backgroundTaskId`, `taskId` of the structured result); a `TaskStop` call starts as a tool call and completes, same item id, as a `command` without `background` when its result names a `local_bash` task —, `background_commands.rs` (pure: the state of each background command, one rule `command_state` for the live republication and every read — the end a stored report proves at its row's time (`killed`/`stopped`/`lost` as `stopped`, no exit code), else what the live session or the holding process proves (`running`, a live report, `stopped` once the launching process is gone), else `unknown` (history alone); an ended state is final), `diffs.rs`, `agents.rs`, `client_tools.rs`), background task reports (`task_reports.rs`: stored `<task-notification>` messages and live `task_notification` frames read into one shape, without Claude's summary pseudo id `__orphan_summary__:<kind>`; a task a previous process left unfinished is `lost` whether reported by the stored aggregate or by its live frame; `task_notifications.rs`: kind and name, status, bounded result and agent thread of the `taskNotification` item), turn outcomes (`result.rs`), `TurnBuilder` (`builder.rs`, shared by live turns and history; `builder/task_items.rs`: report items with ids `{turnId}:notification:{n}`, which never release the held final answer, and the sub-agent item a task's start and report update), and stored messages to turns (`entries.rs`, `segments.rs` — task reports are kept beside a segment's entries, `wake` before a provider turn's first message, `midTurn` at a queued report's position or after the prompt of a user turn that follows buffered wakes, so turn ids, anchors, turn ends and fork cuts never depend on them; wakes an interrupt marker ends before any message are an interrupted turn ending at the marker —, `reconstruct.rs`, `turn_index.rs`). `chain.rs` picks a session file's active branch as Claude's own session read does: the newest leaf walked back through `parentUuid`, with the rows a compaction preserved relinked after its summary, a parentless compact boundary linked to the history it continues, the sibling rows and tool results of each API message merged in, and prompts queued during a turn (`queued_command` attachments a reply follows, and those after the leaf) delivered as queued user messages (a task notification's `commandMode` gives its origin).
- `src/native/` — Claude's session store, read and written by the companion itself. Reads: `LocalSessions`, the indexer's session source: `files.rs` (session and sub-agent files under the projects root, rows, head and tail), `meta.rs` (listing facts from the first and last 64 KiB as Claude's listing reads them: custom else generated title, first prompt, summary, directory with `relocated`, start time, interactive unless an SDK entrypoint or daemon, `continued-in`), `host_state.rs` (the thread state files of `src/state/`, read only: thread identity, session chain, list metadata, turn index, running turn). A listing hides a session another listed session continues. The turns of a session are not read here: `crate::index` indexes them as byte ranges of these files. `host_state.rs` also keeps `HostStateCache`, which reads a thread's `state.json` again only when its size or modification time changed. Transcript reports settle completed runs, while current liveness comes from the shared running-session authority: no live process settles every unresolved run; a replacement process settles only unresolved agent transcripts older than its `startedAt`; an unavailable registry leaves the read unavailable rather than guessing terminal state. The rule is identical for discovered and CodeWide-created sessions. A `SendMessage` call that resumes a finished agent (`resumedAgentId` in its result; a message to a working agent is only queued) starts a new run: the agent and its spawning item are `running` again until a later status fact for that agent settles it; an older unreported resume cannot override that later report. Writes (`write.rs`, as the SDK's `renameSession`, `deleteSession` and `forkSession` made them on local files): a rename appends one `custom-title` row; a removal deletes the session file and the session's directory beside it; a fork writes a new session file with fresh message uuids into the source's project, through a temporary file renamed into place. A session is looked up in its working directory's project, else in any project (newest copy wins). `fork_cut.rs` decides which sessions of a thread's chain a fork copies and through which message, `fork_branch.rs` where the SDK's fork cuts one file, `fork_copy.rs` the copied rows.
- `src/indexer.rs` — `ClaudeIndexer`: the startup backfill and every later listing pass over `native::LocalSessions` (sessions whose size and modification time match the index are not passed again unless their indexed sub-agent set still contains `running`; such a pass reads no file, only settles the sub-agents again against the facts and the process activity; sessions no longer listed are removed); watcher changes, finished live turns and running-session activity changes each pass the session (`index::session`); a session the store no longer has is removed with its search documents. A session whose pass fails is logged with its session id (`warn`/`error`, never content), skipped and retried, so it cannot keep the other sessions out of the index; until the retry succeeds the catalog is not marked current and the thread service answers `thread.list`. Each pass logs `Claude session index pass finished` at `info` with the listed, read and failed counts.
- `src/index/` — Claude's files on the shared segmented offset index (`agent_index::segment`): `line.rs` (one stored row read only as far as the scan needs it: borrowed raw fields, no `serde_json::Value` tree), `source.rs` (`ClaudeSource`, the `SegmentSource` of a session file or a sub-agent transcript: turn boundaries from `transcript::segments::decide`, the one rule history reads share; a turn woken by task notifications starts at its first wake; a main-conversation prompt or resume that starts a turn and whose `parentUuid` is a row before the newest entry — not one the newest compaction preserved — rolls back to that row; every main-level row is keyed by its uuid; facts per session: the newest sub-agent status per agent and spawning call from stored and queued reports and resuming `SendMessage` results, the first final state per background task, and which queued prompts a reply followed; a prompt Claude queued while no turn with messages was open waits for the next reply — delivered, it takes its place in the turns — or for the person's next message — dropped, as Claude's own branch drops it; facts from rows on a branch the person rewound past still count, since a task report states that a process ended and a rewind returns the conversation, not the process), `project.rs` (one turn read back from its byte range and replayed from its start state through the `TurnBuilder`), `read.rs` (pages across a thread's session chain, newest share of a turn id winning, settled with the session's facts and its recorded activity; the running turn's snapshot placed on the newest page), `history.rs` (`IndexedHistory`: `thread.turns` pages, search windows, child threads and their pages, resources from digests), `sessions.rs` (`SessionIndex`: the one owner of session passes for the indexer and the thread service, one pass per session at a time, publishing sub-agent and history changes; the indexer requires a confirmed running-session read, a service read takes the latest known activity), `session.rs` (one session pass: its file and sub-agent transcripts advanced from their checkpoints, a bounded rescan when a turn index hint changed, digests and search documents of the turns whose range moved, the session row recomputed). Hint contract: prompt uuids are recorded in `state.json` before the prompt reaches `claude` (`session/turn.rs` persists the turn record before `offer`), so a prompt's record is scanned with its hint; the first frame of a provider turn is recorded only after Claude reports it, so a pass compares the hints with those the file was scanned with and rescans from the turn before the earliest record a changed hint names. `testing.rs` (tests only) reads a whole session back as `NativeSessionReadResult`; `native/parity_tests.rs` (ignored, opt-in) dumps those reads of a store snapshot to compare two builds; `examples/index_memory.rs` measures the peak memory an index step adds.
- `src/preview.rs` — the thread preview rule (`AgentThread.preview` is the newest conversation message): a turn's last final answer when finished, else its last agent or user message (user text through `ClaudeUserText`), whitespace collapsed, 200 UTF-16 units. `src/store.rs` stores each session's newest message (`StoredSession.newest_message`); a thread's preview is its newest session's, else its first prompt. The adapter overlays it on `thread.list` rows and `thread.read` results the thread service answers (the service projects only the first prompt), and the indexer puts it on every `HistoryChange`.
- `src/catalog.rs` — the Claude thread catalog from the index: `thread.list` rows from indexed sessions and their CodeWide metadata (`NativeSession.codewide`), with the thread service's listing semantics (archive scope and shells, `cwd`, search over name else first prompt, sort keys with `recencyAt` falling back to `updatedAt`, windows, the `v1:<sortKey>:<direction>:<valueSec>:<id>` cursor, at most 500 rows). Deleted threads and programmatic sessions CodeWide never touched are not listed; the name is the latest store title of the chain under the CodeWide title override.
- `src/resources.rs` — thread resources of Claude threads: the shared `agent-resources` reads over projections built from the resources each turn's digest keeps (`index::history`; no turn is read). A thread not indexed yet is served as an empty projection in the working directory its live `thread/settings/updated` reported (kept per thread until `thread/deleted`), so the VCS overlay and the live overlay still apply; without either the read fails with "Claude thread is not indexed".
- `src/search.rs` — `ClaudeSearch`: the `agent-search` full-text index of indexed threads (`<state dir>/claude-message-search.sqlite`): user and agent messages as documents, written per turn as an index pass reads a turn again and removed as turns go (`documents::replace_turns`; a turn a later session of the thread holds stays that session's), positioned by session and start offset (the position each session was indexed at is kept, `claude_session_positions`; a session that joins its chain before sessions indexed earlier rewrites that thread's documents once); `companion/search` and `companion/search/context` in the shared semantics, and windows as neutral summary turns read from their byte ranges (projected by the companion).
- `src/user_text.rs` — `ClaudeUserText`, Claude Code's own formats in user text (command and local-command records, task notifications, the local-command caveat, interruption markers, the compaction summary, appended system reminders); declared through `AgentProvider::user_text_cleaner` and used by thread-list previews.
- `src/storage.rs` — `ClaudeStorage`: the index, the search and resource reads, the watcher and the indexer, and the freshness rules. Indexed history answers `thread.turns` only while no turn of the thread runs and no re-read of one of its sessions is pending; a page reads its own turns' byte ranges off the async runtime, and a file that changed since it was indexed (`ReadError::Behind`) sends the call to the thread service. The catalog answers `thread.list` only after a listing pass matched the thread service's listing, while no turn runs and no re-read is pending; a `thread.updated` the index would list differently (rename, archive, settings, times) schedules a new listing pass and the thread service answers until it ends. Otherwise the thread service answers, reading Claude's store directly.

## Known live/history differences

Background task reports: see `docs/agent-providers.md` (Claude native index, task reports). Unconfirmed: a report of a stopped task delivered live may be missing from Claude's store, so it can vanish after the next re-index.

## Capabilities

- `CAPABILITIES` (constant): `turns.steer`, `turns.providerInitiated`, `turns.startWhileActive: busy`, `threads.hostMintedIds`, `threads.externalDiscovery`, `threads.compact`, `threads.fork`, `requests.userInput`, `orchestration.tools`, `threads.crossProviderFork`, `threads.backgroundTaskOutput`, `accounts.rateLimitResets`.
- `accounts.rateLimitResets` reports the `cedar_ember` grant inventory from `get_usage` and owns `companion/providerRateLimits/reset/consume {providerId, grantId}`. Claude's headless control protocol has no consume request, so the Rust adapter first probes the CLI (which owns OAuth refresh), borrows the resulting access token for one reset request, then probes again and publishes the authoritative inventory. Calls are serialized, grant/provider ids are validated, and neither credentials nor response bodies are logged.
- `threads.backgroundTaskOutput`: a background `Bash` or `Monitor` call's `command` item names the task it started and its state (`background`, from the structured tool result and the task's reports), and `thread.backgroundTask.read` pages that task's output file (`src/background_tasks/`).
- `threads.hostMintedIds` and `threads.externalDiscovery`: CodeWide threads are bound at `thread/start` (companion-minted UUIDv7); sessions started in a terminal or IDE are listed and discovered like Codex CLI threads (`thread.owns` answers from the index, then the thread service; the binding backfill pages `thread.list`, from the index once fresh).
- `threads.fork`: a same-provider fork copies the thread's session chain up to the boundary into new Claude sessions (`native/write.rs`).
- `history.messageSearch`, `history.threadResources` and `subagentThreads` are added exactly when storage is attached (`companion/threadSubagents/read` and the `subagents` of `companion/thread/sync` read the child rows the index publishes). A re-read after which a session's sub-agents list differently (one appeared or left, or its running state, nickname, role or parent changed; timestamps alone do not count) reports a `SubagentsChange` for its thread, whether a live turn runs or not: a background sub-agent's report arrives in a later turn than its spawning item, so no live event of the spawning turn announces the change.

## Binding segments and provenance

- Phase 1: a Claude thread is one binding segment whose native thread id is the app thread id. Every turn and item this adapter returns or emits carries `provenance {provider: "claude", nativeThreadId}`.
- The index is keyed by the `appThreadId` of the thread state files and does not know bindings. A native session that continues another app thread (a non-first segment) is hidden by the companion (thread list rows, global search hits, binding observation), not by this adapter.

## Boundary

- Must not depend on `companion-core` or `agent-provider-codex`.
- Never emits client-wire JSON and never shapes ids for the client; `agent/client_wire` does that (`wire-request-ids-v0`).
- Reads Claude's session store under `<config dir>/projects` and writes it only as described in `src/native/` (a rename appends a row, a fork writes a new session file, a removal deletes a session's files); it never rewrites an existing row. It never writes Claude's settings files. The watcher reads directory entries and file metadata only.
- Reads a background task's output file under Claude's temporary directory (`<temp root>/claude-<uid>/<project key>/<session id>/tasks/<task id>.output`) only for a task the thread's own items launched or reported, never a path a caller names, and never writes there (`src/background_tasks/`).
- Its own files are the thread state under the journal directory (`src/state/`), its derived tables in `state.redb` and `claude-message-search.sqlite`. It never touches `CODEX_HOME`.
- Does not persist, forward or log Claude credentials, tokens or `ANTHROPIC_*` values. The reset operation alone reads Claude's current OAuth access token (or `CLAUDE_CODE_OAUTH_TOKEN`) after a CLI-owned refresh and retains it only for that request. From the user's Claude `settings.json` only the standard proxy variables of `env` are read.

## Install and configuration contract

- Nothing is shipped or installed for Claude: the user installs and signs in to the `claude` CLI.
- `src/config.rs`: every `providers.claude` field is optional and falls back to `ClaudeDefaults` (`src/discovery.rs`: `claude` found on the login-shell `PATH`, the companion's `PATH`, then `~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`; the login-shell `PATH`; `<state dir>/claude-journal`). Fields: `claudeExecutable`, `journalDirectory`, `idleReleaseMinutes` (default 30, 5–240), `environment`. The former host's fields `hostExecutable`, `agentSdk`, `runtimeExecutable` and `sidecarEntry` are accepted and ignored, so an existing entry keeps Claude running.
- Without an entry Claude runs whenever `claude` is found (otherwise one `info` log, "Claude is not enabled"); `"claude": false` disables it.
- Optional `environment` with only `PATH` (absolute directories) and `CLAUDE_CONFIG_DIR` (absolute); any other key invalidates the entry, so no credential can be configured. The `claude` children get `PATH` = dirname(`claudeExecutable`), then `environment.PATH`, else the login-shell `PATH`, else the companion's own; `CLAUDE_CONFIG_DIR` when configured; and the proxy variables (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` and their lowercase forms) set in the user's Claude `settings.json` `env`. An unreadable or invalid `settings.json` leaves Claude unavailable rather than starting it without the user's proxy. The watcher uses the same `CLAUDE_CONFIG_DIR`.
- `src/legacy_install.rs` removes the former host's files on every start (see [Module jobs](#module-jobs)).
- An invalid entry disables Claude with one `error` log carrying the full `err`; Codex is unaffected. Storage that cannot be opened is logged at `error`; the provider then answers from Claude's files alone.
- `"claude": false` disables Claude: calls on Claude threads return `-32070`; bindings, the journal and the index stay. So does a configured Claude that cannot start (see Health above).

## Turn boundaries

Claude owns where a live turn ends; the adapter never infers it from a result's `origin`. The session tracks two facts Claude reports:

- its session state (`system/session_state_changed`: `idle`, `running`, `requires_action`). `idle` comes after the last result once Claude holds nothing; a background agent keeps Claude `running` between its turns, a background shell task does not;
- the lifecycle of every message the companion writes (`command_lifecycle` by the message's uuid: `queued`, `started`, `completed`, `cancelled`), whether a prompt, a steer, the resume prompt or `/compact`.

A turn ends once every message written to the open query is `completed` or `cancelled` and a result arrived since the latest of them `started`, in whichever order Claude reports the two; or once Claude is `idle`, which settles every message it had acknowledged (one still unacknowledged is on its way, and the turn waits for it). Results before that only update the turn's outcome. So a steer's `aborted_*` result, a wake Claude answers before a queued user message, and a user message Claude takes into a wake that has already started all stay in the user's turn, and a turn never outlives the work Claude reports. Claude's `running` while no turn runs starts a provider turn, so a start during Claude's own work answers `busy`; a turn whose last message Claude completed ends while a background agent still works, and the user can write again.

## Supervision and failure

- No child is supervised: the provider status stays `live`. Each live thread runs its own `claude` process, opened by a turn and released after the idle timeout (never while a turn runs or a request is pending; background tasks defer release up to 4 h). The live session count is logged at `info` on every open and release.
- A `claude` process that exits during a turn fails only that turn ("Claude process exited unexpectedly"); its open requests are resolved first and the next turn resumes the session. A lost session is replaced once per turn by a new session with a bounded history prefix; a second loss fails the turn.
- An interrupt answers at once; without the turn's end within 5 s the process is closed and the turn finalized as interrupted.
- A `claude` whose `initialize` answer has no `session_state` cannot report when its turn ends: the session closes it and fails the turn ("Claude Code <version> cannot report when a turn ends…", kind `provider`).
- A companion restart finalizes a turn left in progress (`active-turn.json`) as interrupted on load.
- On companion shutdown (`AgentProvider::shutdown`) every session is closed at once and the adapter waits up to 10 s until the `claude` processes have read the end of their input and exited on their own; a process still running is killed when the runtime drops.
- No live-session cap.

## Live check

`pnpm claude:live` (`scripts/claude-live/run`) drives the `claude_live` example of `apps/companion-linux` through the user's real `claude` on their Claude login: turns, approvals, a client tool, interrupt, steer, a permission switch, user input, compaction, a restart and a sub-agent, each in its own process with a clean environment and a recorder in front of `claude` (argv, environment, every stdin and stdout line). It runs only on request. `scripts/claude-live/compare.py <run A> <run B>` compares two runs' command lines, environments, written lines and control traffic, e.g. before and after a `claude` upgrade.
