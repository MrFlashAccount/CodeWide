# Android TypeScript environments

`pnpm typecheck` runs three Android checks:

- `apps/android/tsconfig.json` checks Android application sources against the native runtime. Its shared `tsconfig.native.base.json` retains Expo's compiler defaults, selects ES2024 without DOM, loads React Native types explicitly, and resolves `.android`, `.native`, then unsuffixed modules. V2 uses the same runtime boundary through `tsconfig.v2.json`.
- `apps/android/tsconfig.web.json` checks all Expo routes and browser entrypoints with `.web` module resolution, the browser export condition, and DOM libraries. Imported shared modules are checked as part of that graph. Native-only files are not browser entrypoints.
- `apps/android/tsconfig.compatibility.json` retains coverage of unsuffixed fallback files and compiles the native/web bridge compatibility assertions in `test/types/platform-contracts.ts`. It supplements both runtime-specific checks.

Node scripts keep their existing separate `scripts/tsconfig.json`. Tests run in their Node test environment; their globals must not become native application globals.

## Native globals

`apps/android/types/native-runtime.d.ts` fills gaps in React Native's declarations with a limited set of APIs verified in the installed runtime:

| API | Runtime owner |
| --- | --- |
| `performance.now`, `queueMicrotask` | React Native `Libraries/Core/setUpPerformance.js`, `setUpTimers.js` |
| UTF-8 `TextEncoder` | Hermes; also documented by Expo `src/winter/TextDecoder.ts` |
| `TextDecoder`, `DOMException`, `structuredClone` | Expo `src/winter/runtime.native.ts` and its implementations |
| `crypto.getRandomValues`, `crypto.randomUUID` | Application boot `src/polyfills/secure-crypto.ts` |
| `HeadersInit` | Derived from the native `Headers` constructor |

These declarations describe runtime availability, not permission to use an API contrary to project architecture rules. For example, the existing prohibition on general-purpose cloning still applies. Do not import DOM or Node declarations to fill a native typing gap. Verify the installed implementation and add only the supported contract. TypeScript declarations cannot guarantee that every runtime implements every declared method.

`test/native-runtime-types.test.ts` compiles a probe together with the **complete V1 and V2 source graphs**, preserving transitive dependency declarations. It verifies supported APIs and requires compilation failures for `AbortSignal.throwIfAborted`, `document`, `Buffer`, and `crypto.subtle`. This catches accidental DOM/Node ambient pollution that an isolated fixture would miss. Existing attachment-cache adapter tests separately exercise cancellation with React Native's actual AbortController dependency.

## Browser contracts and package fixes

Browser database adapters and native implementations share the `*-contract.ts` interfaces. Unsupported Android operations still reject explicitly; typechecking does not implement a browser transport. Browser placeholder collections are real local collections rather than `null as never`.

The installed package versions need three repository-owned pnpm patches:

- `@legendapp/list@3.3.5`: the published `react-native` browser export pointed at the plain React DOM implementation, and `react-native.web.d.ts` duplicated the DOM types. The patch selects the RN implementation for React Native Web and removes the conflicting declaration so the existing RN public contract is selected. The separate `/react` entrypoint stays available for DOM consumers. This matches the [library's RN Web guidance](https://legendapp.com/open-source/list/v3/guides/).
- `expo-video@57.0.3`: browser factories construct `VideoPlayerWeb`, but their declarations returned the narrower base interface, which `VideoView.web` rejected. Source annotations and declarations now express the concrete returned class.
- `expo-status-bar@57.0.1`: the browser no-op accepts the shared props and setter signatures; its source annotations and declarations match that contract.

`test:web-platform` renders the actual installed list in Chromium and verifies RN padding, custom scroll components, scroll events, and reaching the final item. The regular web build also validates Expo Router's route settings; the workspace initial route is `servers/index`.

V1 and V2 browser diagrams share `@codewide/rendering-core/ascii`. Its bundled WASM loader avoids unsupported direct `.wasm` imports in Metro, validates the generated module's exports, and retains a separate DOM-enabled package check. The existing asset synchronization command updates its generated bytes. Native applications continue using the native renderer.

Validation: `pnpm typecheck`, `pnpm test`, `pnpm --filter @codewide/android lint`, `pnpm --filter @codewide/android test:web-platform`, `pnpm --filter @codewide/android build`, and `pnpm validate:android:v2`.
