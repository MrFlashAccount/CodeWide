Strict projection

Render authority

Conversation content comes from the server projection. A locally invented turn is never inserted into the timeline.

Reconnect

Resources reopen the authenticated session, refresh the bounded snapshot, and resume live updates.

Ordering

Refresh generations prevent an older overlapping response from replacing newer authority.

Recovery

Subscription retry remains active through long outages and refreshes after a live subscription is restored.

Durable command rule

  1. The UI acquires a local activation lock before command allocation.
  2. The operation store commits the command and its stable operation id.
  3. The store commit is the only retry boundary.
  4. Post-commit observers are diagnostics only; their failure cannot reject or duplicate the committed command.
  5. The client rechecks the live transport lease and epoch immediately before transition and send.
  6. Reconnect or process restart continues recovery with the same operation id.

Exact correlation and settlement

Correlation is content-free and scoped by saved server, surface, and optional thread. A lock is released only by an authoritative typed settlement with the same correlation id and operation id.

List absence is not proof of non-creation. A terminal-looking state without an exact receipt remains durable and unsettled.

Security and test boundary

Production

V2 uses the same secure saved-server identity and authenticated shared transport as the rest of the app.

Emulator faulting

Fault control exists only in a Cargo-feature-gated Companion build and requires authentication. Android production has no E2E control hook.

Lease ownership

Requests are registered and released within bounded race-safe ownership. Reinitialization moves authority without parallel client projection ownership.

Implemented UI surfaces

Server list and pairing, confirmed saved-server deletion, thread list, new thread, conversation with Voice input, model/settings controls, attachments, changes, image and video preview, terminal, ports, and agents use the V2 route and runtime boundaries.

Explicit exclusions

  • Physical-device Voice capture/cancel, Terminal interruption, and deletion-across-restart proof remain user-run follow-up evidence.

Verification contract

  • Sync-client and Companion unit and integration suites.
  • Strict TypeScript, OXLint, OXFMT, dependency, KNIP, Kotlin, Rustfmt, Clippy, and security gates.
  • Rendered New Thread and Conversation tests for pending, rejection, typed completion, indeterminate, expired, and failed outcomes.
  • Six-scenario Appium emulator E2E with causal event ordering and screen/video evidence.

The executable suite is scripts/test-android-e2e. Detailed architecture is also maintained in docs/android-v2-client-architecture.md.
