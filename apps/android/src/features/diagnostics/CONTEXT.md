# V1 diagnostics

TypeScript/TSX owns recovery-thread intents and diagnostic presentation. Public surfaces are PerformanceDiagnostics, renderRecovery, conversationDiagnosticCapabilities and ThreadNavigationCommit. Other features cannot import private sampling, report-copy, chart or style owners. Timing storage, native tracing, transport telemetry and performance switches retain their existing lower authorities.

PerformanceDiagnostics composes the existing monitoring session, clipboard snapshot action and memory report/reclamation action. Session experiments retain generation guards and restore their previous switch on cancellation/unmount. Report actions keep independent pending guards and copied-feedback timers. Sampling, memory deltas, formatting and chart display have separate private owners; this extraction adds no telemetry fields or collection work. Explicit user activation remains required by the existing UI for copying a report or running reclamation.

renderRecovery creates repair/unsupported/render-failure threads through the same narrow project, rename and submission capabilities. It does not move session, error serialization or persistence into UI. ThreadNavigationCommit reports existing commit metrics with the same lifetimes.

M8 closes the last PerformanceDiagnostics module family and its settings consumer. The final V1 gate is recorded in the migration ledger; actual Android performance experiments and same-device timing comparison remain unverified.

`PerformanceSampleDetails` renders the available sample and experiment controls from the monitoring owner; report, snapshot and reclamation state remain independent.
