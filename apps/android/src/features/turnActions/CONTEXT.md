# V1 turnActions

Qualified thread mutation intents and header/rename presentation.

Public surfaces: ThreadActions, ThreadForkSheet, ThreadRenameDialog, threadRename, turnActions, turnActionCapabilities, forkTargets, forkTargetPicker.

Header and list call the same lower mutation authority. Selection cleanup follows successful mutations; fork publishes the returned qualified id.

Fork: the header's "Fork thread" (whole history) and a message's "Fork" (`lastTurnId` through that turn) open one sheet titled "Fork". `forkTargetPicker` is the conversation-scoped owner of the open sheet and its history boundary; the conversation header renders `ThreadForkSheet` outside the menu's read-only gate, so a message fork in a read-only thread opens it too. `forkTargets` reads the offer when the user forks, never during render: the thread's current model is the server-reported model the composer chip shows for the thread (`projectedThreadExecutionSettings`, without the composer's unconfirmed local overlay), resolved against the thread provider's catalog row and shown with its provider mark. It is preselected, and Fork with it sends the unchanged request (target `null`: same agent and settings). Changing the model is optional and uses the composer's shared model rows (`ui/ModelChoiceList`, grouped under `ModelProviderHeader` when several providers are offered); any other model adds `codewideAgentProvider` and `model` to `thread/fork`, and picking the current model again restores the plain fork. A model of another provider forks into another agent, which cannot continue the chat as is: the Companion starts it from a summary of the conversation (the context handoff), and the sheet says so under the model while such a model is chosen. Offered models are the thread provider's models with `threads.fork` and the other providers' models with `threads.crossProviderFork`; only provider-annotated catalog rows can name a target. A legacy thread without a descriptor forks with its own agent and is offered the whole annotated catalog. An agent with only `threads.crossProviderFork` has no current model to keep: the sheet opens with its list expanded and Fork stays disabled until a model is chosen. Without either capability the Fork actions stay hidden (`threadOffersFork`). Thinking level and a task prompt are not part of the fork. No branch depends on a provider id or name. Copy feedback and rename pending/error behavior retain their original lifetime.

Imports: lower data/platform/shared UI and declared peer public capabilities only. Private views, styles, policy helpers and React hooks remain local; no RemoteWorkspace or root import.

M3 source extraction is implemented. Verification: V1 native/web/compatibility typing, ESLint/dependency graph; thread-fork; fork-targets; v1-fork-sheet.render; thread-rename-dialog.render; native-app-config. Actual Android interaction and same-device performance remain unverified because no device is attached.

M7 capability closure: `workspaceCapabilities.ts` exposes only this owner's qualified operations. Private `workspaceAdapter.ts` binds existing lower model/session authority through exact workspace composition; it does not own shared in-flight maps, runtime construction or global cleanup. The broad RemoteWorkspace facade is deleted.
