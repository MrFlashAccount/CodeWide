# V1 turnActions

Qualified thread mutation intents and header/rename presentation.

Public surfaces: ThreadActions, ThreadForkSheet, ThreadRenameDialog, threadRename, turnActions, turnActionCapabilities, forkTargets, forkTargetPicker.

Header and list call the same lower mutation authority. Selection cleanup follows successful mutations; fork publishes the returned qualified id.

Fork: the header's "Fork thread" (whole history) and a message's "Fork" (`lastTurnId` through that turn) open one sheet titled "Fork chat", which names the kept history ("The whole chat", "Up to this message"). `forkTargetPicker` is the conversation-scoped owner of the open sheet and its history boundary; the conversation header renders `ThreadForkSheet` outside the menu's read-only gate, so a message fork in a read-only thread opens it too. `forkTargets` reads the offer when the user forks, never during render: the thread's current settings are the server-reported model, thinking level and service tier the composer chips show (`projectedThreadExecutionSettings`, without the composer's unconfirmed local overlay), the model resolved against the thread provider's catalog row. The sheet asks who continues first: one card per offered agent, the thread's own agent first ("Keeps the full history") and every other provider ("Starts from a summary"). Another agent cannot continue the chat as is: the Companion starts it from a summary of the conversation (the context handoff), and the sheet says so under the cards while such an agent is chosen. Then the chosen agent's model (its own models only, the composer's shared `ModelDisclosure`/`ModelChoiceList` rows, with the shared `FastModeToggle` when the model has a Fast tier) and its thinking level on the model menu's slider (`ui/ThinkingLevelSlider`, `CodeWideSlider` on native). Picking an agent preselects the thread's own settings or that agent's default model with its default level; switching models keeps the chosen level and Fast when the new model offers them. The thread's own agent and settings, unchanged, fork with target `null` (the plain request); any other choice names `{provider, model, effort, serviceTier}`, sent as `codewideAgentProvider`, `model`, `config.model_reasoning_effort` and `serviceTier`. The primary action names the outcome ("Fork chat", "Fork into <agent>") above a one-line summary of the choice. Offered models are the thread provider's models with `threads.fork` and the other providers' models with `threads.crossProviderFork`; only provider-annotated catalog rows can name a target. A legacy thread without a descriptor forks with its own agent and is offered the whole annotated catalog. An agent with only `threads.crossProviderFork` shows its own card disabled and preselects the first other agent. Without either capability the Fork actions stay hidden (`threadOffersFork`). A task prompt is not part of the fork. No branch depends on a provider id or name. Copy feedback and rename pending/error behavior retain their original lifetime.

Imports: lower data/platform/shared UI and declared peer public capabilities only. Private views, styles, policy helpers and React hooks remain local; no RemoteWorkspace or root import.

M3 source extraction is implemented. Verification: V1 native/web/compatibility typing, ESLint/dependency graph; thread-fork; fork-targets; v1-fork-sheet.render; thread-rename-dialog.render; native-app-config. Actual Android interaction and same-device performance remain unverified because no device is attached.

M7 capability closure: `workspaceCapabilities.ts` exposes only this owner's qualified operations. Private `workspaceAdapter.ts` binds existing lower model/session authority through exact workspace composition; it does not own shared in-flight maps, runtime construction or global cleanup. The broad RemoteWorkspace facade is deleted.
