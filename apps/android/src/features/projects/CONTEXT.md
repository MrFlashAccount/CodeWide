# V1 projects

This TypeScript/TSX owner handles project catalog selection/order/pinning, directory browsing, new-chat draft choice and project changes before the first message. The lower remote-project model, preference persistence and shared catalog resource remain authoritative. No project feature starts transport or creates a replacement cache.

Pin/unpin and add commands publish their validated RPC acknowledgement immediately to the shared catalog. The lower model retains an acknowledgement even before first resource demand and overlays stale cache/list responses until a later list observes the acknowledged pin/name and recency. A read started before that acknowledgement cannot confirm it; after confirmation, subsequent external edits are authoritative again. `remote-project-catalog-model.test.ts` and `v1-project-pin-acknowledgement.render.test.tsx` cover stale synchronization and mounted management/sidebar publication without reload or reconnect.

Public entrypoints are ProjectDirectoryPicker, ProjectPickerSheet and its input contract; projectSelection/projectWorkspace, activeProjectSelection and composerProjectSelection; NewChatProjectPicker/newChatEntry/newChatProjectSelection/NewThreadFloatingButton; and SidebarProjectViews/sidebarProjects presentation contracts. Router owns the former mounted picker and new-thread destination composition. Picker sessions, row projection, management state, leaf views and styles are private. Peer imports are limited to public connection display and navigation contracts.

Workspace selection and sheet state survive ordinary chat changes. Each picker retains its open/reset behavior, stable home/directory resource keys and errors; directory loads happen through the existing render resource. Project sections retain pinned/recent/other order and expansion. Pending management changes remain owned by that mounted sheet. New chat opens a local draft and counter identity; remote creation still belongs to first submission. Changing an existing empty thread checks both turns and queued messages, selects the replacement before deleting the old thread, and preserves failures.

Composer picker state uses the existing conversation-scope reset and activation owner. A completed change cannot close or clear a replacement activation's picker. Lower workspace support, catalog and directory capabilities retain the same qualified keys and completion behavior.

M2 evidence includes project routing/order/catalog/workspace tests, management render tests, stale project-completion render coverage and the V1 gate. Native folder selection, actual new-chat submission and device back-navigation smoke remain explicitly pending.

M7 capability closure: `workspaceCapabilities.ts` exposes only this owner's qualified operations. Private `workspaceAdapter.ts` binds existing lower model/session authority through exact workspace composition; it does not own shared in-flight maps, runtime construction or global cleanup. The broad RemoteWorkspace facade is deleted.

`newChatSubmission.ts` owns first-send orchestration: isolated workspace creation precedes thread admission, and navigation follows successful send admission. Rejection preserves the current draft. `projects-workspace-adapter.test.ts` and `new-chat-submission.test.ts` verify this ordering and identity-preserving current-workspace options.

New Chat opens the retained draft immediately. Only its composer project action opens the aggregate project sheet. Server chips are local picker filters: selection never changes the sidebar server scope. Every row and directory resource retains server identity, including identical paths. Folder browsing uses a concrete filtered server; under All, its navigation entry opens the server catalogue inside the same sheet. Server defaults remain separately qualified under All. Clickable breadcrumbs connect Servers, the server root and every folder ancestor. The folder browser has no filter chips: its Servers breadcrumb opens the server catalogue, and a server row opens that server's filesystem root. Project filter chips stay on Choose project and Manage Projects. Changing servers resets path and query without changing the project-list filter. The root is derived from that server's qualified Home response, including Windows drive roots. Selecting a folder for a draft does not register or pin a project; management adds the folder before closing. Choose another folder is a compact secondary button. Manage Projects is available only on the project-selection page; folder navigation uses Back. Selection says Choose folder and Use this folder; management says Add project and Add this folder. The management directory entrypoint receives all saved servers and retains qualified remote reads and additions. Management has local server chips that filter its rows; its plus opens the filtered server's browser directly or requires a server choice under All, without an Add on server section. No empty pinned group reserves space before history. Programmatic hiding and stale native dismissal callbacks cannot dismiss a replacement route. Draft destination changes retain identity and text; uploaded attachments remain bound to their original server. Management reads all servers independently of the sidebar filter. A dismissed picker cannot navigate after a delayed folder-add completion; catalog acknowledgements remain authoritative.

Pinned project shortcuts expose only Unpin and Mark all as read in the transient native row popup. Unpin is an explicit false assignment, then publishes the validated acknowledgement through the existing shared catalog. Mark all as read delegates to the summary database: its serialized write captures all persisted unread rows for the exact connection/path, including rows beyond loaded pages, and publishes read boundaries together. Later activity becomes unread again. Row popup anchoring/recycling belongs to the shared UI mechanism; project commands and errors remain here.
