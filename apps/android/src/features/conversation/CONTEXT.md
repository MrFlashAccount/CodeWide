# V1 conversation ownership

M6–M8 source extraction is implemented. The temporary command aggregation and lower facade are deleted. ConversationWorkspace receives owner-qualified capabilities and explicit model reads; private scope binding and render factories preserve the original mounted hierarchy.

ConversationWorkspace composes public feature capabilities. ConversationDetail owns model reads and progressive restoration; it publishes its snapshot through a render slot. ConversationReadSurface composes only read capabilities, timeline and read-only slots for subagents. ConversationComposition assembles the main editor and tools through their public owner entrypoints. A thread whose `canAcceptDirectInput` is `false` renders read-only (`data/threadDirectInput.ts`): a sub-agent, which its parent agent drives, or a thread another app holds (open elsewhere: refuses input and has no `parentThreadId`). Only an open-elsewhere thread shows the persistent `ui/ThreadOpenElsewhereNotice` bar in the editor's place under the read-only composer chips, instead of a matching send failure: "Open in another app" (pressing it opens a details popover: what the lock means and what both actions do), a Fork button that opens the fork sheet for the whole chat, and the primary Check again, which re-reads the thread authoritatively (`surface.recheckThread`; the label shimmers while it runs). Its header keeps the thread menu with only Compact context and Delete thread off; sub-agents have no menu. The live `thread/status/changed` patch, or a check that finds the thread released, removes the bar. Private frame, chrome, timeline and overlay factories preserve the original view hierarchy without adding component mount boundaries.

Timeline owners preserve initial-position identity, history anchors, search paging, unread receipts, gesture trimming and activation cleanup. Turn/protocol/content modules retain projection caches, bounded rendering and native reveal. Dependency rules forbid full workspace/composer/tool composition imports from detail, read surface, timeline, turns, protocol and content. Native keyboard geometry remains active while fullscreen coverage pauses tail following and paging.

Main selection still publishes cached content and hydrates history progressively. After the bottom chrome is measured, a nonempty data-ready timeline mounts behind the transcript boundary until LegendList reports `onReady`. An initial unread target is then measured against the usable viewport between the header and composer; any required nonanimated correction completes before the one-way per-chat reveal. The first completed agent turn that makes a thread unread owns this initial anchor across later completions and a trailing in-progress turn; tail-follow is admitted only when no unread anchor exists, and an explicit gesture or jump releases that anchor. The transcript skeleton appears only when loading or positioning exceeds 200 ms, and no refresh, unread or cursor state participates in this presentation gate. Persisted composer state is a progressive render resource: the canonical `ConversationLayout`, header and timeline mount immediately, while only the composer slot shows its geometry-preserving placeholder until restoration completes. Composer restoration precedes editing; the ready editor then stays mounted. Subagent selection retains its Transition and does not construct main editor/upload/queue-edit/voice bindings. JS runtime startup is separate from native boot and feature lifetime.

Validation: V1 gate (2422 modules, 9100 dependencies), history/projection/output/streaming and repaired source contracts, 21 render cases across five suites, Android/web Expo export. Actual device gestures, native retained view behavior and relative performance remain unverified. The final full Vitest run passes 2213 tests; completed final platform validation and device limits are recorded in the migration ledger.

`workspaceCapabilities.ts` is the public qualified scroll/history contract. The private `workspaceAdapter.ts` binds the shared ThreadUiState seed and existing thread-sync reads only from exact workspace composition; it creates no timeline cache.

Private composition seams: `activeConversationScope` resolves the destination; `ConversationDestinationSurface` renders its existing boundary; `mainConversationHistory` binds history resources and `MainConversationPublication` publishes cached snapshots. `conversationScopeFeatures` and `conversationSurfaceAssembly` compose the main editor/tools. `readConversationTimelineBindings` and `ReadConversationLayout` compose the subagent read surface. Timeline gesture/measurement callbacks retain `useEvent` and original ref handles. Turn user/agent body and protocol presentation factories preserve element order and reuse the coupled public ToolContent declarations. No factory adds mounted state or a fetch effect.

Turn content preparation is shared across physical timeline slices through a 64-entry working-set cache keyed by immutable TimelineItem identity. A new source snapshot invalidates preparation; search focus, fork availability and pending-request visibility are applied independently. Cache eviction changes work only, never visible content. Changes footer parsing happens on explicit open; it passes the latest recorded turn patch and qualified target to the existing shared viewer.

Every turn is its own agent bubble. A turn without a user message (a background task woke the agent) is never folded into a neighbouring turn: Claude answers each wake as a separate turn, and an earlier answer may hold a question for the person. Such a turn has no lead row and no pre-turn lifecycle: all of its work is the response. A completed wake that produced nothing (`isEmptyWake`: no answer, activity or artifacts; unloaded content without Companion totals counts as unknown) draws no rows. Rows never depend on neighbouring turns, so the resident history range may begin or end at any turn. A running turn folds its current group of tool calls (`ActiveTurnActivity`) like the collapsed groups between its texts: one row with the whole group's count, which opens a sheet with every call of the group (including the start the render window keeps unmaterialized), plus only the calls running now (else the newest one). Its texts stay visible; thinking and subagent rows keep their own presentation. Background task reports (`codewideTaskNotification` items, parsed once in `rendering/taskNotifications.ts`) are never turn activity. A wake turn draws the reports that woke it, and those that arrived while it answered, as one line outside the bubble in its lead row; a person's turn draws its mid-turn reports as that line after its bubble. Consecutive wakes that produced nothing merge their lines, and the run joins the next wake's line; only lines merge, never turn content. The line shows an avatar stack, a short label and a status, and opens a list whose agent rows open the agent's thread. Subagents still working (`rendering/runningAgents.ts`, Claude only: launch state plus later reports; a primary provider's launch items keep their launch state) appear as one chip next to the live plan above the composer. A finished turn that started subagents (`rendering/launchedAgents.ts`, its `spawnAgent` calls) shows them as one chip at the top of its bubble, since its launch rows fold into the history; the chip shows names and opens their threads, not status, because only the running-agents chip knows who still works. A running turn keeps its visible launch rows and shows no launch chip. A merged reason line keeps its first wake's row key and date while later wakes join it. Compact stored turns (`compactCompletedTurnForStorage`) keep reports and launches resident, and a summarised wake without a report (an older Companion) is unknown, never hidden.

Activity counters, output-token estimates and estimated input cost are server-owned projections. TurnMetricsProvider supplies validated figures; range selectors match exact item IDs and never derive totals from visible command output. Full activity hydration retains range metadata on its first item. Missing attribution stays unknown. See docs/android-activity-metrics.md for the versioned contract.
