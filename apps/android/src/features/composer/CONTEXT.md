# V1 composer

Goal editing reuses the resident composer, not a separate form. `composerGoalMode.ts` owns a selection-local Legend create/edit intent; `composerGoalSubmission.ts` maps Send to a goal update without admitting a user turn or changing its status/budget. A separate goal-edit session leaves the live message draft and attachments resident; removing Goal or successful submission returns to that draft. Settlement is qualified to the original mode owner, and later typing is not discarded. Failed goal edits recover into their editor session, never into the durable message draft of a departed chat.

M5 is implemented. `ComposerFeature` composes the resident editor, context strip, queue edit bar, attachment tray and actions. `ComposerEditor`, `ComposerMicrophone` and `ComposerSubmitAction` preserve native element placement and the mounted editor across draft selection. `ComposerMenu` owns controls/skills intents; route-owned `ComposerControlRoute`, `ComposerActionRoutes`, and `ComposerRuntimeRoutes` present the retained tool activation.

`draft.ts` selects the shared lower seed, reads existing ThreadUiState, owns editor/selection/latest-value refs and persists changes. `settings.ts` owns local preferences, control requests and the settings overlay. A new chat keeps model, thinking, Fast and access choices as local preferences and sends them with its first message. An existing thread shows its server settings (`thread/settings/updated` echo or snapshot); a change is sent once through `thread/settings/update` and shown by `settings/controlsOverlay.ts` only while the server still reports the value it replaced. Its echo confirms it, any other server value replaces it, and a rejection removes it and shows the server's error. `thread/settings/update` settles through the native outbox (`data/nativeCommandSettlement.ts`): it resolves on delivery, rejects on an RPC error and stays pending while queued offline. `settings/composerControlsView.ts` derives what the chips and the route-owned control sheet show, including a model without thinking levels (no effort) and a change made during a running turn that applies from the next turn (model, thinking and Fast always; access on the primary provider, and to or from read-only on a neutral provider). "Server default" access is the absence of a choice in a new chat and, in an existing thread, the provider's default profile sent explicitly (`settings/permissionDefault.ts`), because an absent profile means "unchanged" on the wire. `submission.ts` owns one-shot delivery choice and failed pre-admission recovery. `queueEdit.ts` keeps queue editing and uploads in their distinct scope. `attachments/attachmentAdmission.ts`, `attachmentRemoval.ts`, `largePaste.ts` and `reviewAdmission.ts` own draft admission, removal, paste conversion and review acknowledgement. `suggestions.ts` owns skill insertion and selection. `voice.ts` binds the existing retained VoiceInputController; it does not acquire a second recording runtime or dispose JS on feature unmount.

Escaping callbacks use useEvent. Delayed operations capture ordinary activation-owned draft/preferences/upload/send callbacks before awaiting or binding: they must not resolve a new chat through a latest-value callback on settlement. Recovery preserves newer typing, restores a departed chat durably and respects a same-scope replacement owner. Final voice text is supplied explicitly. Drawing and review capture the same draft admission capability before asynchronous work.

Stopping a turn with an active Goal is a composed lifecycle action: pause the authoritative Goal first, then interrupt that exact turn. A failed pause leaves the turn running so Stop cannot create a new automatic Goal continuation while presenting itself as successful. Ordinary non-Goal Stop remains a direct turn interruption.

`composerContinuation.ts` selects Play from the authoritative current outcome or a resumable Goal, independently of history pagination. Empty interrupted/failed work uses `continuationAdapter.ts` to validate the latest server turn and start a new turn with empty input; it creates no user message. Goal continuation uses the existing captured status capability and never sends a second turn/start. Composer-owned Legend admission survives remounts, retains accepted/uncertain outcomes until work advances, and keeps late error presentation activation-qualified. Drafts, attachments, voice and queue editing retain their existing actions. `continuationFailure.ts` distinguishes explicit request rejection from an unconfirmed start; uncertain delivery is not repeated. See [continuation semantics and verification](../../../../../docs/android-composer-continuation.md).

Canonical ThreadUiState, ComposerUploads, FileTransferController, VoiceInputController and workspace resources remain lower authorities. Tool pages and tool context chips enter through display slots and public intents. No new protocol, state machine, database, runtime disposal or optimistic entity is introduced.

Validation: M5 V1 gate passed native/web/compatibility typing and lint, 2286 modules/8194 dependencies. Focused composer/upload/voice/queue contracts: 103 passing tests; updated native integration contracts: 21 passing tests. Seven render suites passed 35 tests; the extended native editor suite passed 11 tests including the new retained-editor assertion (36 unique tests across that combined scope). Android and web Expo exports completed. Actual device microphone, gestures, keyboard, background/foreground and performance parity remain unverified under the resolved no-device stop. M6–M8 source ownership is now closed; see the canonical ledger for final evidence.

M7 capability closure: `workspaceCapabilities.ts` exposes only this owner's qualified operations. Private `workspaceAdapter.ts` binds existing lower model/session authority through exact workspace composition; it does not own shared in-flight maps, runtime construction or global cleanup. The broad RemoteWorkspace facade is deleted.
