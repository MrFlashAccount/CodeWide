# V1 settings

TypeScript/TSX owns settings visibility and section composition. App-lock authority remains `ui/AppLockGate`; Android exposes only V1 and has no generation selector. M1 source migration is implemented. The device biometric control has not been exercised on this host.

Public surfaces: `SubscribedConnectionSettings` and `useSettingsVisibility` in `SettingsFeature`. The workspace retains the hook's existing lifetime. Settings reads the existing account database query and composes public connection settings records, security controls, diagnostics and version. Connection editors and account login state stay with their feature owners.

Advanced Settings exposes the device-wide timeline row premeasurement experiment. It is fail-disabled: the default path passes only the 115 dp list estimate and lets LegendList measure rendered rows. Enabling the flag opts into exact per-row hints; switching strategy invalidates only LegendList size caches and does not remount the conversation.

The `Voice Assistant` page composes independent device-wide settings. Global Voice remains Live/realtime V3 only and exposes no mode selector. `globalVoicePreferences` owns only the synthesized realtime voice identifier and retains the legacy `global-voice` record. `voiceAssistantPersonality` retains its versioned behavior profile for compatibility, while Settings presents one unlabeled Personality field and clears the retired communication-style and rules fields on the next explicit save. `voiceAssistantBackgroundModel` owns a separate versioned model-and-reasoning preference for the hidden text thread; it migrates the earlier model-only record, resolves the persisted values against the ordinary chat `model/list` catalog and falls back to valid catalog defaults when either selection disappears. The page presents one compact `Agent model` row and opens the same `ModelThinkingMenu` used by the composer. Opening the Voice Assistant page first projects the newest model list already held by the shared turn-controls resource and calls the shared `turn-controls-loader` only when no catalog is resident; there is no manual load/refresh control or product-local model list. Model-specific preset personality remains hidden because the independent free-form Voice Assistant personality below is authoritative. `globalVoiceOrbStyle` owns only the floating overlay renderer choice; a missing, obsolete or corrupt record resolves to Particles, while an explicit saved Nebula or Particles choice remains unchanged. `personalVoiceFilterPreferences` owns the fail-disabled experiment flag; the native filter owner separately stores only its local spectral profile and never stores captured PCM. Settings may compose these contracts for presentation, but no codec, persistence write or runtime read may absorb another. A missing personality or background-model record preserves the pre-profile supervisor behavior and server-default model respectively.

Personality edits are explicit-save drafts. The settings feature owns pending, duplicate suppression and visible save failure; the shared user-preferences database owns durable serialization. A saved profile applies when the next Voice Assistant activation builds `realtimeStartInstructions` and the developer-role realtime startup item used by the first turn, including when an existing hidden thread is restored. The same profile is included when a replacement hidden supervisor thread is created. The activation captures that profile once; it is not appended on every turn. A completed home-thread `contextCompaction` reasserts the captured instructions through developer-role realtime context, without reading a newer draft or mutating the selected synthesized voice. Changing the profile therefore affects the next explicit activation, not the active session.

Audio input retains its native preference and lease owner but is not exposed on the Voice Assistant settings page. It persists route kind only and resolves connected device ids at use time. Native overlay Settings opens this page through the settings route with an entry request nonce. See `docs/global-voice-audio-input.md` at the repository root for capture and restoration contracts.

Personal voice enrollment is an explicit six-second microphone action. The switch remains unavailable until native enrollment succeeds, and a preference change applies to the next WebRTC session. Disabling the experiment restores the ordinary WebRTC path without deleting the local profile.

`SettingsSheet` retains its selected-server navigation, back behavior, refreshed content and overview fallback when a selected server disappears. Servers are the only headed overview section. Security, Voice Assistant and Advanced form one list; Security opens a dedicated page whose current control is Biometric Lock. Closing/reopening and adding a server preserve the existing callback order. `SettingsVersion` preserves clipboard and version presentation. It may consume the process-owned Android APK release availability resource and expose a link to the fixed GitHub Releases page when the manifest contains a newer stable APK version. This informational check remains separate from signed OTA bundle prefetching and never installs an APK. No settings action disposes or reconstructs the application runtime.

Each server page renders the Connections-owned Companion update projection. Settings owns neither HTTP/session access nor update operation state: it shows the current and available versions, platform, capability and durable terminal result, confirms the temporary disconnect plus automatic rollback, then emits the exact displayed target fingerprint. Pending activation preserves and shimmers the current version text; a disconnect does not remove the server or clear the operation.

Allowed imports are connection public capabilities and existing shared data/UI/boot authorities. Private cross-feature imports, V2 runtime/storage, lower-to-feature edges and full RemoteWorkspace contracts are forbidden. The experiment and diagnostics modules stay at their current paths until their approved units migrate.
