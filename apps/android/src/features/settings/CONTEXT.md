# V1 settings

TypeScript/TSX owns settings visibility and section composition. App-lock authority remains `ui/AppLockGate`; Android exposes only V1 and has no generation selector. M1 source migration is implemented. The device biometric control has not been exercised on this host.

Public surfaces: `SubscribedConnectionSettings` and `useSettingsVisibility` in `SettingsFeature`. The workspace retains the hook's existing lifetime. Settings reads the existing account database query and composes public connection settings records, security controls, diagnostics and version. Connection editors and account login state stay with their feature owners.

The `Voice Assistant` page composes independent device-wide settings. `globalVoicePreferences` owns only the synthesized realtime voice identifier and retains the legacy `global-voice` record. `voiceAssistantPersonality` retains its versioned behavior profile for compatibility, while Settings presents one unlabeled Personality field and clears the retired communication-style and rules fields on the next explicit save. `globalVoiceOrbStyle` owns only the floating overlay renderer choice; a missing, obsolete or corrupt record resolves to Particles, while an explicit saved Nebula or Particles choice remains unchanged. `personalVoiceFilterPreferences` owns the fail-disabled experiment flag; the native filter owner separately stores only its local spectral profile and never stores captured PCM. Settings may compose these contracts for presentation, but no codec, persistence write or runtime read may absorb another. A missing personality record preserves the pre-profile supervisor behavior.

Personality edits are explicit-save drafts. The settings feature owns pending, duplicate suppression and visible save failure; the shared user-preferences database owns durable serialization. A saved profile applies when the next Voice Assistant activation builds `realtimeStartInstructions`, and the same profile is included when a replacement hidden supervisor thread is created. The activation captures that profile once; a completed home-thread `contextCompaction` reasserts the captured instructions through developer-role realtime context, without reading a newer draft or mutating the selected synthesized voice.

Audio input retains its native preference and lease owner but is not exposed on the Voice Assistant settings page. It persists route kind only and resolves connected device ids at use time. Native overlay Settings opens this page through the settings route with an entry request nonce. See `docs/global-voice-audio-input.md` at the repository root for capture and restoration contracts.

Personal voice enrollment is an explicit six-second microphone action. The switch remains unavailable until native enrollment succeeds, and a preference change applies to the next WebRTC session. Disabling the experiment restores the ordinary WebRTC path without deleting the local profile.

`SettingsSheet` retains its selected-server navigation, back behavior, refreshed content and overview fallback when a selected server disappears. Servers are the only headed overview section. Security, Voice Assistant and Advanced form one list; Security opens a dedicated page whose current control is Biometric Lock. Closing/reopening and adding a server preserve the existing callback order. `SettingsVersion` preserves clipboard and version presentation. No settings action disposes or reconstructs the application runtime.

Allowed imports are connection public capabilities and existing shared data/UI/boot authorities. Private cross-feature imports, V2 runtime/storage, lower-to-feature edges and full RemoteWorkspace contracts are forbidden. The experiment and diagnostics modules stay at their current paths until their approved units migrate.
