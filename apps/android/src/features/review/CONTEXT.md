# V1 review

Public surfaces: ReviewFeature binds the mounted review session; comments/CommentSheet is the one line comment composer, with comments/lineCommentDrafts (its per-line text owner) and comments/CommentDestinationPicker, comments/DraftCard (saved drafts and `DraftPutCard` for new drafts not saved yet) and comments/destinationPolicy presenting companion-owned drafts with their Agent | PR | Both destinations and per-axis badges; guide/GuidePanel walks an agent-written guide over a caller-owned diff source; reviewTargetCapabilities (bound by reviewTargetAdapter) mutate drafts and guides; workspace/CodeReviewWorkspace presents the current thread's own file changes without a guide entry; ReviewTargetSheet chooses the existing review command; comments/reviewSubmission prepares text attachments; resources/reviewFiles converts received change resources. Resource loading, line comments, voice binding and view settings have private owners.

The feature owns the complete code review editor. `editor/` contains the native and web adapters (one props contract, `editor/codeReviewEditorProps.ts`), typed bridge and display policy. `editor/webview/` is the browser-only Pierre application and its authored HTML template; `sync-code-review-editor-asset.mjs` bundles that entry into Android assets. The browser entry uses a `.web.ts` suffix so the web TypeScript graph checks its DOM contract while the native graph excludes it. Generated Android assets are outputs, not source owners. The WebView only displays: the document, the tree, inline comments (`saved`, `pending` with its text under a CSS text shimmer, `failed` with the owner's reason) and the anchor line the host sends as `selection`. It reports line taps and never hosts a composer; there is no draft, voice or submit message on the bridge.

Line composer: a line tap, in the PR Changes tab and in the current-thread review workspace alike, opens exactly one native `CommentSheet` (an `AppSheet`): the chat composer's public Markdown input, the chat composer's public microphone and recording meter over the retained VoiceInputController (`comments/lineCommentVoice.ts`; no second recording runtime), the caller's accessory (the PR destination picker) and Send. The tapped line stays highlighted as its anchor while the sheet is open. Send never waits for a write: the sheet closes at once and hands the text to its owner, so it has no busy state and stays dismissible (the Material sheet hides its drag handle whenever pan-to-close is disabled). Send while recording finishes the dictation and sends its final text. Unsent text lives per line in `lineCommentDrafts` and outlives the sheet; a voice binding captures its line, so a transcript that arrives after the sheet closed or another line opened lands on the line it started on (the voice scope is the review window plus the line).

Source publishes before diff completion. Abort checks guard publication and final materialization; existing async-resource keys and revision identities remain authoritative. Composer owns draft attachment admission and identity-checked acknowledgement through its reviewAdmission capability. The shared `rendering/ContentReviewHost` remains outside this feature because Markdown, image, diagram and attachment renderers use its cross-renderer selection and session lifetime. The feature does not own those generic annotation primitives.

M4 review: V1 gate passed (2189 modules, 7677 dependencies), 83 focused semantic/source/boundary checks and two render checks passed. Tests preserve delayed line transcript, selected-line isolation and acknowledgement of only the sent attachment. Actual Android voice/WebView interaction remains unverified under the resolved device disclosure.

M7 capability closure: `workspaceCapabilities.ts` exposes only this owner's qualified operations. Private `workspaceAdapter.ts` binds existing lower model/session authority through exact workspace composition; it does not own shared in-flight maps, runtime construction or global cleanup. The broad RemoteWorkspace facade is deleted.

Pull-request review: this feature is forge-independent and must not import `features/pullRequest*`; the PR screen depends on it and owns its separate Files / Guide surface. Drafts and guides are companion-owned (`data/reviewResources.ts`); PR drafts reach a forge only through Submit review on the PR screen. A new draft's `putDraft` is the persisted durable write; until the drafts snapshot holds it, `data/reviewDraftPuts.ts` lists it from the shared MutationCache (saving, or refused with the Companion's reason), so callers show it at once without awaiting. On acknowledgement the adapter patches the saved draft into the drafts query and forgets the write in the same task, then re-reads; a refused new draft stays listed until `dismissDraftPut` (restore or discard), a refused re-anchor is dropped. Session and VCS line comments keep the existing local list and composer review admission, but the current-thread Changes workspace never exposes the pull-request guide. Guide prose is untrusted agent output, rendered as plain text and labelled with its author thread.
