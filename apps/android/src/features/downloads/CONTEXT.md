# V1 downloads

Public surfaces: `DownloadsSheet` lists this device's downloads by day, newest first, and exposes the Chrome-style per-file controls: pause, resume and cancel for unfinished downloads, retry for failed or cancelled ones started in this process, and open, share, rename, remove from list and delete for completed files. Search filters filenames within their original day sections. Long press or Select enters multiselect; the toolbar can share finished files together or delete the selection. Delete removes saved documents from storage, while Remove from list keeps them. A rename records the display name and URI returned by Android. The remembered download folder is a device setting: Settings shows and changes it in its Downloads section (`features/settings/DownloadSettings`), as Chrome keeps Download location in its settings rather than in the list. `useDownloadsActivity` projects overall progress of running downloads for an indicator outside the sheet; the thread-list menu draws it as a ring in place of its `⋮` glyph and leads to the sheet through its Downloads item.

Route composition owns the sheet's visibility and passes `openDownloads` to the thread-list headers, like the terminal manager. The feature reads the process `DownloadManager` (`data/downloadManager.ts`) through `DownloadManagerProvider`; it owns presentation only. It does not start transfers, persist history, pick folders or touch files itself: those remain the manager's and the native file layer's.

The manager admits a single transfer for each destination folder and sanitized filename. On repeat requests it also considers previously recorded URIs for this source in the selected folder, including renamed files. It checks the actual file against the source's size and SHA-256 before fetching ranges. Completed history identifies a saved file by its device URI. On restore the manager keeps the newest completed row per URI, preserving separate copies and unfinished attempts.

Unfinished downloads do not survive the app process: they reload as `interrupted`, with only Remove, because the transfer access lived in the previous process. Downloads run in JavaScript and can be throttled while the app is in the background; there is no system notification or foreground service. Physical-device verification of the Storage Access Framework folder grant across restarts, partial-file cleanup and background behaviour remains pending.
